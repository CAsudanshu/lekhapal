# LekhaPal – developer notes

Developed by CA Sudanshu Mallick. Plain HTML + JavaScript, no build step: edit a file, refresh the browser.
Any developer (or any AI assistant) can change it from these notes.

## Editions
* `E.edition` = `NP` or `INTL`; `CFG()` in core.js returns currency, locale, tax name, tax-ID label and FY start for the open entity.
* In INTL, `toBS`/`toAD` pass AD dates through, fiscal years follow `E.intl.fyStart`, and `localizeDOM` rewrites Nepal words on screen (BS, PAN, TDS, IRD, NFRS, Rs) to the international equivalents.
* Licence payload field `ed` (`NP`/`INTL`/`ALL`) controls which editions an install may open.

## Accounting model
* Every entry is a voucher with balanced `lines` `{l: ledgerId, dr, cr}`. Sales/Purchase/CN/DN carry a `bill`; lines are generated by `buildBillLines`.
* Periodic inventory (like Tally): purchases go to Purchase ledger; closing stock is computed from item movements and shown in P&L/BS.
* Books never need year-closing: profit of earlier years flows to retained earnings automatically (`cumProfit`).
* Ledger → group → FS head decides the NFRS line and cash-flow class; a ledger can override with `fs`.

## Common changes
* VAT rate: Settings (per entity). TDS rates: just type % in entries.
* New default ledger/group: `defaultLedgers` / `defaultGroups` in `entity.js` (affects new entities only).
* Due dates: `complianceDue` in `entity.js`.
* Seeded Nepal updates: `SEED_UPDATES` in `tools.js` (or publish `updates.json`).
* Licence trial length: `TRIAL_DAYS` in `auth.js`.
* Keep `ADMIN-PRIVATE-LICENSE-KEY.json` private. If lost, generate a new key pair and replace `DEV_PUBKEY` (old licence keys then stop working).
